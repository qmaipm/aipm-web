# 现场与管理系统页规划 v2（2026-10-28）

> 接 docs/PRODUCT-SYSTEMS.md。v1 列了 7 个系统；v2 根据用户补充（服务感知 = 巡更轨迹、消防巡查、飞行检查、工时四层、月报数据量）又调研了一轮，调整了页面清单和标题用词。**本文件只是方案，还没有改页面。**
>
> 原则：标题和首段只用客户在搜的词和传统系统的痛点；我们自己的叫法（服务感知、项目大脑、工时漏斗）只在正文里用来解释。

## 一、调研方法

- 百度联想词：两轮一共约 200 个词。联想词出现，说明有人在搜；长尾内容说明用户实际在问什么。
- 外部资料：同类产品怎么介绍自己（巡更、工牌定位、劳动力管理、消防巡查），新闻里的争议，以及法规原文。
- 站内盘点：服务感知在 /products/iot 已公开的部分，以及现有真实界面截图。

## 二、v2 新发现

### 1. 客户嘴里没有"服务感知"，只有"人员轨迹""智能工牌""保洁定位"

| 词 | 百度联想（节选） | 结论 |
|---|---|---|
| 人员轨迹管理 | 人员轨迹管理系统、人员轨迹管理软件、人员轨迹管理 app、**人员定位及轨迹管理是否合法** | 有需求，也有顾虑，两样都要回答 |
| 人员轨迹管理系统 | 有哪些、app、软件 | 适合做系统页标题 |
| 员工轨迹 | 员工轨迹管理系统、员工轨迹定位、**监控员工轨迹合法吗** | 同上 |
| 智能工牌 | 智能工牌是干嘛用的、智能工牌的定位功能、**智能工牌监听合法吗** | 客户叫"智能工牌"，不叫"行为传感器" |
| 工牌定位 | **工牌定位的三大害处**、工牌定位漏洞最简单三个步骤、工牌定位合法吗 | 一线员工抵触明显 |
| 保洁定位系统 | 保洁定位系统软件、app、有哪些；**保洁频次监测智能系统** | 保洁场景的客户原话 |
| 保洁轨迹 / 清洁轨迹 | 没有相关联想（只有推拉门轨道、保洁短剧） | **不能用作标题** |
| 人员定位系统 | 多是煤矿、隧道、化工厂（UWB） | 工业场景为主，物业只能顺带 |

**同类产品现状**：工牌定位厂商卖的都是"实时位置 + 轨迹回放 + 停留时长 + 电子围栏 + 脱岗告警 + SOS"。所以光说"能出轨迹"不算差异。

**舆论风险**：新华网 2026-01-29《给环卫工戴定位器，"智慧管理"不能让技术失了温度》，起因是环卫工说"工牌有定位，不动要被罚款"。文章的建议是：轨迹用来改进路线、统计作业覆盖，不要用来盯人。

**我们的差异**（用户口述 + /products/iot 已公开）：
1. **按服务点位记录，不是盯人**。空间传感器装在服务点位上，智能工牌（行为传感器）由员工佩戴。记录的是"什么时候进了哪个点位、停留多久、做了没有"，不是 24 小时实时盯位置。iot 页已公开：蓝牙广播、不收集其它数据。
2. **一套感知，所有工种共用**。点位传感器布一次，清洁、工程、安保都能用；已经给保洁布了点位的项目，安保只要加智能工牌。同类产品是巡更一套、保洁一套、工程巡检一套。
3. **停留时长精确**。不只是打卡那一刻，而是完整还原在每个点位停留了多久。站内真实界面 op-sensor.webp（点位日报）有"进入时间、离开时间、停留时长"。
4. **数据直接用起来**：生成巡更报告、品质评分、工时漏斗、工单，不只是一张轨迹图。

**定位建议**：系统页标题用"人员轨迹管理系统"（客户原话），首段就回答"按服务点位记录、只在工作时间、用于服务记录和工时核算"。FAQ 正面回答"人员轨迹管理合法吗"。这个问题 AI 经常被问，现在没人认真答，是 GEO 的机会；但我们不给法律意见，只讲做法。

### 2. 消防巡查：合规刚需，搜索量比巡更还大

| 词 | 百度联想（节选） |
|---|---|
| 消防巡查记录 | 消防巡查记录表、填写模板、**多久巡查一次**、**保存多久**、台账模板 |
| 消防巡查频次 | **每两小时一次**、每天几次、需要 2 小时一次吗 |
| 防火巡查 | 防火巡查记录表、多久一次、**防火巡查与防火检查的区别**、每日几次 |
| 消防控制室巡查 | 消防控制室巡查记录表、**巡查记录需要拍照片吗** |
| 消防巡查系统 | 消防巡查系统软件、有哪些、app |
| 消防巡检系统 | 哪家好、有哪些、**必须做**、报价；但也有消防巡检柜、接线图 |
| 物业消防 | 物业最怕消防查什么、物业检查消防一般检查什么 |
| EHS / 双重预防 / 隐患排查系统 | 以工厂和企业安全生产为主 |

**法规依据**（公安部令第 61 号《机关、团体、企业、事业单位消防安全管理规定》，应急管理部官网）：消防安全重点单位应当进行每日防火巡查；公众聚集场所在营业期间的防火巡查应当至少每二小时一次。巡查记录要写明巡查人员、时间、部位、内容、发现的隐患及处理措施，并签名。上海地标 DB31/T 540-2022 也写了"营业期间至少每 2h 巡查一次"。

**痛点**：每 2 小时一次、每次都要记录签名。纸质记录或扫码打卡只能证明"到过"，不能证明"看了什么"；补填记录也很难发现。安保兼做消防巡查的项目，管理层很难核实。

**我们的差异**：停留时长证明在点位停够了时间；手机拍照，AI 识别消防通道堵塞、灭火器状态等问题；隐患直接生成工单；按 61 号令要求的字段自动生成巡查记录台账。

**用词**："消防巡检系统"也指消防泵的巡检柜（硬件），标题要用"消防巡查系统"，正文再带上"消防巡检"。EHS 是工厂的词，物业客户不这么搜，不追。

### 3. 飞行检查：集团品质部门的痛点，有明确搜索

| 词 | 百度联想（节选） |
|---|---|
| 物业飞行检查 | **是什么意思**、涉及秩序有哪些、检查内容、记录表 |
| 物业飞检 | **一般查什么**、有哪些项目、**最怕三个原因**、**飞检如何查审物业夜班** |
| 物业集团巡查 / 联合巡查 | 巡查内容、记录表 |
| 物业第三方评估 | 机构、公司排名、**费用**、报告、需要什么资质 |
| 物业服务第三方考核 | 有 |
| 物业品质督导 | 工作内容、督导内容有哪些 |

**痛点**：集团或区域去项目现场检查，要差旅、要人、还要供应商陪同，所以一年去不了几次；夜班基本查不到；每个人打分标准不一样。用户提到某大型国有上市物业公司一次区域巡查要 7 到 8 万元，**这个数字不披露**，只写"差旅和人员成本高、频次低"。

**我们的差异**（真实界面 qa-system.png 已能看到）：
- AI 先自动判断"环境档次与空间类型"（比如高档办公区茶水间），再匹配对应的评分标准。
- 自动做"问题识别与责任归属"，列出责任部门、基础扣分、加重扣分。像消防通道里的装修垃圾这类扯皮问题，系统直接划分责任。
- 现场任何人拍照，效果和检查人自己拍一样。飞检可以远程做，次数随时加。
- 夜班的在场情况由传感器数据说明。

### 4. 工时：客户不搜"工时漏斗"，但搜它的每一层

| 词 | 百度联想（节选） | 用途 |
|---|---|---|
| 工时漏斗 | 没有相关联想 | 只在正文里作为我们的解释框架 |
| 考勤工时 | 怎么算、计算公式、**考勤工时和有效工时区别** | 第 2 层 |
| 作业工时 | 如何计算、**跟标准工时的区别** | 第 4 层 |
| 有效工时 | 是什么意思、计算公式、**有效工时利用率一般为多少** | 第 4 层的常用叫法 |
| 工时利用率 | **怎么计算**、一般为多少、**越高越好吗**、合理范围 | 核心概念词 |
| 定岗定编 | 物业定岗定编是什么意思、保洁/保安定岗定编管理制度 | 第 1 层（合同工时）的来源 |
| **物业缺编扣款** | **违法吗、怎么处理、不合理怎么办** | 合同工时和考勤工时对不上，引发争议 |
| 保安排班 | 保安排班表 12 小时、24 小时模板、复杂排班方法、保安排班软件 | 排班入口 |
| 智能排班系统 | 软件、有哪些、操作流程 | 排班入口 |
| 计件工资 / 计件工时 | 工厂为主；"保洁计件"没有联想 | 不追 |
| 劳动力管理系统 | 有，主要是同类厂商的品牌词 | 不追 |
| 物业人力成本 | 包含什么、**占比多少合理**、怎么算 | 文章入口 |

**同类产品现状**：已经有劳动力管理厂商在做物业行业方案（公开案例：某物业公司 66,000 名员工统一考勤）。他们讲的痛点是"出勤数据不透明、跑冒滴漏""缺乏科学的编制计算方法""员工年龄大，智能手机不普及"，做的是考勤、排班、按项目归集工时、看板。**他们的数据停在打卡这一层**，不知道人在不在服务点位、在点位上干了多久。**对外不点名。**

**我们的差异：工时漏斗四层**（用户定义）

| 层 | 含义 | 数据来源 | 回答的问题 |
|---|---|---|---|
| 合同工时 | 和客户约定的人数 × 工时 | 合同（项目大脑初始化时录入） | 约定了多少 |
| 考勤工时 | 实际打了考勤的工时 | 无感考勤（人脸，经本人同意录入） | 来了多少 |
| 在场工时 | 真正在项目现场的工时 | 智能工牌 + 点位传感器 | 在不在 |
| 作业工时 | 在服务点位上消耗的时间（常说的有效工时） | 点位停留记录 | 干了多少 |

每两层之间的落差都对应一个具体问题：
- 合同 → 考勤：缺编，对应"缺编扣款"的争议。
- 考勤 → 在场：打了卡人不在。
- 在场 → 作业：人在，但没在服务点位上。

人效、编制、排班、供应商结算都从这四层数出来。标题用"工时管理系统、有效工时、工时利用率、缺编"，正文再讲漏斗。

### 5. 其他补充（用户已确认）

- **月报数据量**：一个项目一天 500 到 800 万条数据，一份月报要分析 3,000 万条。（待确认能否公开、项目类型怎么写）
- **合同**：上传后由数据本体和模型映射成数据；所有业务结果都在工作流引擎里经人确认后才生效，不会自动改。对外写"人确认后生效"。
- **大屏**：一句话先出初稿，可以一直改到满意；也可以把公司现有的看板直接丢给它照着做，规则也一样。
- **盖雅工场**：做的是工厂方案。之前有 FM 公司用它做计件工时和智能排班，排班确实是痛点。对外不提名字。
